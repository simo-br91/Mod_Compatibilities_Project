# Phase 5 Progress

## Goal area

- Phase 5 source of truth: ML, calibration, and grounded AI UX from `IMPLEMENTATION_PLAN.md`
- Scope implemented as a deterministic, inspectable extension of the Phase 4 recommendation/reporting slice

## What was implemented

- `packages/platform-core` now includes a deterministic `risk_scoring` phase that extracts finding-level feature vectors, persists offline datasets, calibrates finding confidence, and materializes grounded pack-review summaries.
- Analysis results now carry `featureDataset`, `featureVectors`, `calibratedScores`, and `reviewSummary` alongside findings, recommendations, recommendation sets, and reports.
- Recommendation generation now benefits from calibrated finding confidence rather than only pre-Phase-5 heuristic confidence.
- Reports now include grounded review output that cites concrete finding, evidence, and recommendation IDs instead of free-floating summary text.
- Gateway surfaces now expose `GET /v1/analyses/:analysisId/ml/features` and `GET /v1/analyses/:analysisId/review-summary`.
- `apps/ml` is no longer a pure placeholder: it now provides deterministic feature calibration and grounded-summary helpers with Python tests.

## Contract updates

- Shared domain and API contracts now cover finding feature vectors, offline datasets, calibrated finding scores, and pack review summaries.
- `schemas/json/` now includes machine-readable schemas for:
  - `finding-feature-vector`
  - `offline-dataset`
  - `calibrated-finding-score`
  - `pack-review-summary`
- `schemas/openapi/platform.openapi.yaml` now documents the new feature-dataset and review-summary endpoints plus the richer analysis-report payload.
- `schemas/sql/postgres_core.sql` now includes persistence contracts for model registry entries, feature vectors, offline datasets, calibrated finding scores, and pack review summaries.
- Analysis phase enums are now aligned across runtime and contracts to include `risk_scoring`.

## Deterministic fixtures and model assets

- Replayable Phase 5 truth data lives under `fixtures/ml/phase5-analysis-truth-set.json`.
- Deterministic model manifests live under:
  - `models/registry/phase5-deterministic-models.json`
  - `models/features/phase5-finding-risk-features.json`
- The in-memory repository seeds active deterministic model registry entries for finding-risk calibration and grounded summaries.

## Usable flow

- `platform.orchestrator.createAnalysis(...)` now executes:
  - `evidence_enrichment`
  - `risk_scoring`
  - `recommendation`
  - `reporting`
- `platform.ml.getDatasetForAnalysis(...)` retrieves the generated offline dataset, feature vectors, and calibrated scores.
- `platform.ml.getReviewSummary(...)` retrieves the grounded pack review summary for an analysis.
- `platform.reports.getReport(...)` now returns review-summary content inside the persisted report surface.

## Validation

- `pnpm contracts:check`
- `pnpm --filter @modcompat/gateway exec tsx src/index.ts`
- `python -m unittest discover -s tests` from `apps/ml` with `PYTHONPATH` pointed at `apps/ml/src`
- `go test ./...` from `apps/recommendation` with `GOCACHE` pointed at the workspace-local `.gocache`

## Validation blockers

- `pnpm --filter @modcompat/platform-core test` remains blocked in this sandbox because Node's test runner attempts to spawn worker processes and fails with `spawn EPERM`.
- The same test suite runs outside this sandbox and should be used there as the strongest TypeScript verification path.

## Remaining gaps

- Feature datasets, calibrated scores, model registry entries, and grounded review summaries remain in-memory only; SQL contracts are ready, but no durable adapter is wired yet.
- Calibration is deterministic and inspectable rather than learned from a real offline training pipeline.
- “Semantic retrieval and reranking” is represented here by deterministic feature extraction and reranking scaffolding, not by embeddings or external vector search yet.
- Grounded summaries are template-driven and citation-backed rather than generated by a live model runtime.
- Model rollout, drift monitoring, and rollback are represented by deterministic registry manifests and statuses, not yet by live deployment control loops.
